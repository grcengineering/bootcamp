# Governance Engineer

**The object it engineers:** the **policy & control architecture** — the organization's single,
versioned, machine-readable source of truth for controls.

## Jobs-to-be-Done
- Make the control framework *code*: adding/changing a framework is a reviewed diff, not a project.
- Keep policy, standards, and cross-framework crosswalks authoritative and current.
- Automate governance / exec / board reporting from the catalog.

## Role Spine (deep)
**Policy-as-Code** (Cedar → OPA/Rego → Kyverno) · the **standards spine** (NIST 800-53 superset +
crosswalks) · **OSCAL authoring + Trestle** · control-catalog versioning · governance/exec
reporting automation. Deep on: 08, 09, 10, 12; working on the Common Core, 13.

## Role Capstone
Convert our control catalog into a **versioned, crosswalked OSCAL source of truth** with one
control's policy enforced as code and exec-reporting auto-generated from it.
