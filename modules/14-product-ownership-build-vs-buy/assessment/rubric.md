# Module 14 — Assessment Rubric

*Each row is Pass / Not-yet. All five rows must be Pass to clear the module. Each row maps to a §1 objective and, on a Not-yet, routes the learner back to a specific concept section — never the whole module. Per-criterion pass-rates are the telemetry that flags this module for revision (maintenance Loop 3).*

| Criterion | Objective | Pass means | On Not-yet return to |
|---|---|---|---|
| Product framing | O1 | The memo names exactly one accountable owner, lists the control's customers in a deliberate priority order, gives a ranked backlog with the highest-risk item near the top, states a UX target (ideally "evidence as a by-product"), and lists ≥4 observable metrics including loss exposure bought down. "Who is it for" is treated as primary, not "does it exist." | §3 (The Mental Model); §4.1–4.2 |
| Quantified gap | O2 | Loss event frequency and loss magnitude are estimated **separately, as ranges** (not points), with a one-line reason they're separate; a sampling calculation produces a **mean AND a tail percentile**; the learner states why the tail (not the mean) is the executive's concern. No red/amber/green cell reasoning anywhere. Numbers reproduce from the stated ranges. | §3; §4.3–4.5; §5.2 |
| Seven-stage map | O3 | All seven loop stages (UNDERSTAND → LOCATE → QUERY → EVALUATE → EVIDENCE → MONITOR → OWN) are scored BUILD / BUY / HYBRID, each row carrying its deciding question and a defensible one-line reason. The deciding question consistently distinguishes undifferentiated breadth from specific judgment/accountability. | §4.6; §5.3 |
| Boundary judgment | O4 | The memo draws an explicit owned-vs-vendor line with a specific call on the EVALUATE/policy-and-evidence layer, and gives **both** one honest vendor-wins case **and** one honest owning-wins case for the same control — avoiding both NIH (build-everything) and vendor-worship (the dashboard-is-green answer). | §4.7–4.8; §5.4 |
| Quantified justification | O5 | The closing recommendation is a decision (not a summary) that ties the boundary explicitly back to the Part-2 loss-exposure number in finance-legible terms (one-time cost vs. recurring expected loss and tail), of the form an auditor and a finance partner would both accept. | §3; §5.2; §5.4 |

---

**Early-warning rows.** "Quantified gap" (O2) and "Boundary judgment" (O4) are the rows expected to fail first as tooling and the continuous-compliance platform market shift; a sustained per-criterion pass-rate below the `assessment_passrate_threshold` in `meta.yaml` (0.80) on either row auto-opens a revision task against this module (Loop 3). The content, not the learner, is treated as the defect.
