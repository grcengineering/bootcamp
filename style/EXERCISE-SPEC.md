# Exercise Spec Format (v1) — `modules/*/exercises/exercise.yaml`

> The exercise layer's content contract. **Specs are data; verifiers are code.** A spec describes
> scenario, seeded state, tasks, hints, and *names* of verification checks — it never contains
> executable logic. The closed verifier vocabulary lives in `web/src/verifiers/` (unit-tested,
> mutation-tested); domain-native test artifacts (pytest assertions, Cedar decision pairs, expected
> SQL result sets) are content assets executed by the engines. `expr:` / `js:` / `script:` fields
> are forbidden and rejected by `exercise-lint`.

## Top-level shape

```yaml
id: lab-01                      # unique, stable
module: 01-terminal-and-command-line-basics
title: Evidence from a raw export
owner: Justin Pagano            # rot-dashboard ownership (root ISC-69)
volatility: B                   # A stable / B environment-dependent / C third-party-coupled
review_due: 2026-12-01
engine: shell-linux             # shell-linux | shell-macos | powershell | python | sql |
                                # policy | api | git | builder | mixed
claim_thread: laptop-encryption # optional; names the "one claim, sixteen ways" connection
payload_budget_bytes: 0         # >0 required when engine is heavy (python, sql, policy)
desktop_recommended: false      # true => UI shows a desktop-class recommendation

seed:                           # the simulated machine's starting state
  profile: m01                  # manifest seed-state id (.ci/fixtures/manifest.yaml)
  home: /home/analyst
  files:                        # VFS contents, sourced from committed fixtures
    - path: lab01/access-export.csv
      from: labs/setup.sh       # provenance: the lab's own setup script defines the bytes
  path_tools: [lab-setup, parse-access-export]   # fictional tools on PATH (fixture-defined)

intro: |
  Original scenario prose. No third-party content (originality-lint runs on this file).

walkthrough_first_input: pwd    # optional guided first-input moment (web ISC-115)

tasks:
  - id: t3
    type: action                # action (machine-gated) | reflection (never machine-gated)
    objective: [4]              # §1 learning-objective number(s) this task exercises
    instruction: |
      Using cat, grep, and wc connected only by pipes, produce the count of access rows
      granting a role that contains "admin".
    verify:                     # ONLY registry primitive names + params (Zod-validated)
      - check: file_content_equals
        path: ~/lab01/evidence-admin-count.txt
        from: generated         # value generated by replaying the reference transcript
      - check: artifact_produced_by
        path: ~/lab01/evidence-admin-count.txt
        min_pipes: 2
        forbidden_commands: [awk, sed, perl, python3]
    hints:                      # ladder: ≥2 rungs, nudge → (concept) → reveal
      - nudge: Which program emits the file? Which keeps only matching lines? Which counts?
      - concept: "§4.3 — the pipe"
      - reveal: cat access-export.csv | grep admin | wc -l
    explain: |                  # post-success reinforcement (why this worked + control link)
      Three small programs and two pipes just evaluated an access-control claim…

completion:
  evidence_pack: true           # appends a hash-chained local evidence record (web ISC-129)
```

## Rules enforced by `.ci/exercise-lint.ts`

1. **Schema** — every field above validates; unknown fields rejected.
2. **Verifier seam** — every `check:` exists in the registry export; params satisfy that
   primitive's schema; fixture match-class is compatible with the primitive kind.
3. **No code in data** — `expr`, `js`, `script`, `eval` keys anywhere → hard fail.
4. **Completability** — every `action` task's instruction + reveal hint use only commands present
   in the module's fidelity-manifest entries (spec↔prose drift tripwire, root ISC-70/74).
5. **Objective coverage** — the union of task `objective` lists covers every §1 objective; tasks
   may be `reflection` type, but ≥1 `action` task per objective unless the objective is
   explanation-only (then `reflection` suffices).
6. **Hint ladder** — every `action` task has ≥2 hint rungs; the last rung is `reveal`.
7. **Originality** — no third-party URLs (originality-lint scope includes `exercises/`).
8. **Quiz ban** — no task may be satisfied by selecting an answer; `verify` must reference
   simulated state, history provenance, or engine results (web ISC — anti-quiz heuristic:
   at least one check per action task is stateful).
9. **Golden + anti-transcripts** — `exercises/transcripts/golden.jsonl` and
   `exercises/transcripts/anti-*.jsonl` exist; `bun test` replays them through the Lab Player
   verifier: golden passes all action tasks, each anti fails its targeted task — and fails it AT
   the `fails_check` index its header names (the H1 discrimination contract; see the Transcript
   format section), so an anti can never pass the gate for the wrong reason (root ISC-73).
10. **Generated expectations** — `from: generated` values come from
    `exercises/transcripts/expectations.json`, produced by replaying the golden transcript
    against the seed; literals for capturable check types are rejected (root ISC-60).

## Transcript format (`exercises/transcripts/*.jsonl`)

One JSON object per line: `{"input": "cat access-export.csv | grep admin | wc -l"}` — exactly what
a learner would type, in order. The replay harness feeds each line to the engine and then runs the
spec's verifiers.

### Anti-transcript header (the discrimination contract)

Every `anti-*.jsonl` begins with a header line that pins the cheat to the *exact* check it must
trip:

```json
{"anti_for": "t3", "fails_check": 1, "reason": "echo-cheat: right bytes, no pipeline — artifact_produced_by (verify[1]) catches it"}
```

- **`anti_for`** (required, string) — the action task this anti targets. Replaying the anti must
  leave this task FAILING.
- **`fails_check`** (required, integer) — the index into the targeted task's `verify[]` array of
  the check that *encodes the cheat*. This is the heart of the H1 fix: it is **not enough** for an
  anti to leave its target failing with a non-empty gap — an anti can fail for the WRONG reason (a
  syntax error in an earlier step, an answer-key mismatch, a typo) while the cheat it names goes
  uncaught. `fails_check` names the specific verifier the cheat must defeat — pick the check that
  discriminates the *concept*, not an incidental side effect:
  - `artifact_produced_by` for echo/awk/printf fabrication (right bytes, wrong provenance);
  - `stream_separated` for evidence/error stream contamination;
  - `script_reproducible` for date- or clock-contaminated evidence (two clean runs disagree);
  - `validator_passes` (exit 0 or exit 1) for a forged/never-earned gate verdict;
  - `api_pull_complete` for incomplete pagination;
  - the per-row `file_content_matches` regex that excludes the dishonest label / wrong control for
    honest-label and orphan-resolution near-misses (the *semantic* gate, not an answer-key);
  - `file_not_matches` for a forbidden anti-pattern (mutating cmdlet, decoy line, reference banner).
- **`full_cheat`** (optional, boolean) — set `true` only when the cheat removes the ENTIRE control
  the target exercises, so EVERY check of the target legitimately fails (e.g. committing straight to
  `main` removes the whole branch→merge change-management control). This is an *audited* exception to
  the surgical-near-miss guard; always pair it with a `reason` that explains why every check fails.
- **`reason`** (required, string) — a sentence naming the cheat AND the discriminating check.

The replay suites (`web/tests/exercise-replay*.test.ts`, via `tests/_anti-discriminate.ts`) enforce,
for every anti: (1) `fails_check` is a valid index; (2) `verify[fails_check]` returned `pass:false`
on the post-replay state (the named cheat is what failed); (3) the target task overall still fails;
and (4) the anti is a near-miss, not a syntax bomb — for full-flow antis every action task before the
target latched; for scoped antis a non-targeted check of the target still passes (unless
`full_cheat`). `.ci/exercise-lint.ts` independently gates (1) at CI time. Set
`ANTI_DISCRIMINATE_DEBUG=1` when authoring a new anti to print the per-index pass/fail vector and
read off the right `fails_check`.

## Fidelity manifest cross-reference

Commands taught/used by a module live in `.ci/fixtures/manifest.yaml` with per-entry
`source` (docker-linux-userland | docker-linux-booted | macos-host | pwsh-authored | wasm-engine |
authored) and `match` class (byte-exact | structured | engine-pinned | synthesized-porcelain |
authored-with-citation | computed). The spec's `seed.profile` keys the seeded state used at capture
time so sim and capture replay identical worlds.
